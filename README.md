# service_bot

Бот в телеграм предназначенный для записи на услуги, напоминании о записи и ведения статистики

### Подготовка к запуску

```bash
git clone https://github.com/ivg97/service_bot.git
cd service_bot
python3.12 -m venv venv
source venv/bin/activate
pip install -r requiremenets.txt
touch .env
```
В файл .env добавить следующие значения:
```text
TELEGRAM_BOT_TOKEN=SECRET_BOT_TOKEN
ADMIN_IDS=123456789
DATABASE_URL=sqlite:///bot.db
```
#### Запуск
`python src/main.py`

Получаете ответ:
```text
2025-09-01 00:50:44,691 - root - INFO - Бот запущен...
2025-09-01 00:50:44,692 - aiogram.dispatcher - INFO - Start polling
2025-09-01 00:50:44,755 - aiogram.dispatcher - INFO - Run polling for bot @name_bot id=id_bot - 'NAME_BOT'
```

### Правила оформления коммитов
Во время разработки приветствуется использование коммитов вида:
`тип(тема): описание`, 

где `тип` - тип коммита, который может быть следующим:

- feat - Добавление новой функциональности;
- fix - Исправление ошибки в существующем коде;
- docs - Изменения, связанные только с документацией;
- style - Изменения, которые не влияют на логику кода (форматирование, пробелы, точки с запятой и т.д.);
- refactor - Переработка кода без добавления новой функциональности и без исправления багов
- perf - Изменения, улучшающие производительность;
- test - Добавление или изменение тестов;
- build - Изменения, влияющие на систему сборки или внешние зависимости;
- ci - Изменения в конфигурации CI/CD (GitHub Actions, GitLab CI, Jenkins и т.д.).;
- chore - Разные мелкие задачи, не относящиеся к другим категориям;
- revert - Откат предыдущего коммита;
- и другие...


Дополнительно возможно использовать !, что означает важность данного коммита:
`feat(api)!: добавлена апи для проверки баланса водителя`

`тема` - тема коммита, которая в одном-двух словах отображает смысл изменений
описание - развернутое описание коммита
